# Emergency QR — проверка объединённого проекта

Дата: 1 октября 2026 года. Windows, Node.js 24.18.0, npm 11.16.0.
Проверены исходные четыре TXT-задания и Word master. Общий контракт во всех
трёх ролевых заданиях совпадает: `emergency-qr-v1`. Задания использованы как
спецификация. Дополнительно выполнен редизайн по предоставленному макету и
подготовлена конфигурация постоянного HTTPS-размещения.

## Результат

Все три части объединены: Expo frontend, Express backend и настоящая SQLite.
Сайт собирается и отдаётся backend, мобильные JS/Hermes-пакеты экспортируются.
Общие команды запуска, настройки и проверки работают из корня проекта.
Итоговый исходный архив — `emergency-qr.zip`; исходные архивы участников сохранены.

Новая версия использует красный акцент `#E51D36`, горные изображения главной
на desktop/mobile, форму из трёх шагов, отдельный профиль, страницы помощи
и информации о проекте. QR остаётся чёрно-белым без наложенного логотипа,
256 px с `quietZone=32`; скачиваемый PNG — 1120×1120. Контракт API не расширялся
полями фото, возраста или датой рождения.

## Что проверено настоящей интеграцией

`frontend/tests/integration.spec.ts` запускает backend отдельным процессом из
посторонней рабочей папки, с временным SQLite-файлом и отдельным web-экспортом.
Процесс действительно останавливается и запускается снова; сохранность данных
не имитируется. После завершения временная база удаляется.

- Создание через интерфейс создаёт запись SQLite; база хранит SHA-256 ключа,
  а не исходный ownerToken. Публичный и секретный токены различаются.
- Второй изолированный браузер читает карточку без Authorization. Публичный
  JSON имеет только разрешённые четыре поля, скрытая заметка равна null.
- Правка через форму сохраняет QR; опубликованная заметка появляется после
  обновления. После перезапуска процесса сохраняются данные, ключ и ссылка.
- Отключение блокирует чтение. Замена QR сохраняет отключённый статус.
  После включения новый QR работает, старый недоступен.
- Старый, неизвестный, отключённый и удалённый публичные токены дают одинаковый
  ответ 404. Публичный токен не позволяет изменять/удалять карточку.
- Удаление через интерфейс убирает запись; ownerToken больше не даёт доступ.
- API и HTML получают no-store; HTML также no-referrer и noindex,nofollow.
  Неизвестные API-пути и отсутствующие assets не подменяются HTML.
- CORS, строгие тела запросов, лимиты и подмена proxy-заголовков дополнительно
  проверены API-тестами; UNIQUE, SQL-параметры и откат миграций — SQLite-тестами.

## Исправленные ошибки при объединении

1. Закрыт обход защиты статических файлов через alias/junction к внутреннему
   скрытому или защищённому каталогу web-экспорта.
2. Устранён HTTP 500 для SPA, если каталог сборки лежит внутри скрытой папки.
3. После успешной правки сбой следующего GET больше не предлагает повторно
   отправить уже сохранённую форму.
4. Раскрытый секретный ключ скрывается при смене маршрута и уходе в фон.
5. Публичный 404 всегда показывает согласованное нейтральное сообщение.
6. Галочка согласия сообщает актуальное состояние через ARIA, включая
   переключение обратно; сохранены native-свойства доступности.
7. Сборка/запуск очищают кеш Metro: ранее смена API URL могла оставлять старый
   адрес в готовом JS. Итоговый LAN URL проверен непосредственно в сборке.
8. Копирование поддерживает локальный HTTP: fallback запускается синхронно
   в событии нажатия, очищает временное поле и не выдаёт отказ за успех.
   Для заблокированного Clipboard остаётся видимая строка ручного копирования.
9. Верхняя и нижняя навигация трёх шагов сохраняют черновик; ошибка поля сервера
   возвращает на нужный шаг. На узком экране верхняя кнопка остаётся доступной.
10. Добавлены скачивание реального PNG и рабочая отправка публичной ссылки.
    Кнопки профиля и мобильные вкладки проверены переходами, а не только внешним видом.
11. `TRUST_PROXY` принимает только явные IP/CIDR. Проверены независимые лимиты
    за доверенным proxy, игнорирование поддельного заголовка от недоверенного
    соединения и отказ опасным настройкам; по умолчанию доверие выключено.

Для исправлений добавлены регрессии. Root-скрипты настройки отдельно проверены
на валидацию IP/HTTPS, запрет неявной перезаписи, `--force`, посторонний cwd и
пути с пробелами. Смена глобальных настроек Windows не выполнялась.

## Сеть и данные текущего запуска

Сайт: `http://ФАКТИЧЕСКИЙ_IP:3001`; API: тот же origin с `/api/v1`.
Актуальные интерфейсы показывает `npm run configure`. Фиксированный LAN-IP
в документации не закреплён: во время работы он менялся при смене сети.
При финальном проходе проверен адрес `192.168.110.112`; это снимок настройки
этого компьютера, а не постоянный адрес для другого устройства или будущей сети.
Постоянная локальная база: `data/emergency-qr.sqlite`. Она может содержать
пользовательские карточки; утверждение о пустой базе не делается. Автоматические
интеграционные тесты используют отдельные временные базы и не очищают её.
Все тестовые данные вымышленные, демо-номер `+999000000001`, реальных звонков нет.

Локальная проверка по адресу сетевого интерфейса на том же компьютере
**не доказывает доступ со второго физического телефона**. После изменения
сети/IP нужно повторить configure с `--force`, сборку и запуск. Старые PNG и
распечатки содержат прежний адрес: получите и сохраните QR заново. Firewall
не отключался.

## Оставшиеся ограничения

- Физические Android/iPhone, Expo Go, реальный SecureStore, системные Share,
  Clipboard и набор номера на устройстве не проверены. Экспорт JS/Hermes —
  не запуск приложения и не APK/IPA. Сценарий двух телефонов приведён в README.
- Npm audit: backend и database — 0 уязвимостей; frontend — **13 moderate**,
  0 high и 0 critical. Это транзитивные зависимости Expo/Router; безопасного
  совместимого исправления в текущих диапазонах не найдено. Принудительное
  понижение Expo и несовместимые overrides не применялись. Подробности в отчёте frontend.
- Ключ web хранится только в памяти. Его нужно сохранить явно; восстановление
  потерянного ключа и полностью потерянного ответа создания контракт не предусматривает.
- Публичный HTTPS-деплой пока не выполнен. Для подготовленной конфигурации
  Docker/Caddy проверен `compose config`; Docker Engine в среде недоступен.
  Сборка образа, запуск контейнеров, домен и TLS-сертификат не проверены.
  Инструкция: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
- APK/IPA, публикация в магазинах и полноценные аккаунты не созданы.
  Демонстрационный прототип не заявляется готовым к медицинской эксплуатации.

## Передача

В `emergency-qr.zip` входят исходники всех трёх модулей, тесты, миграция,
lock-файлы, примеры окружения, скрипты, инструкции и подготовленные файлы
`deployment/`. Нет `node_modules`,
реальных `.env`, SQLite, ключей, тестовых артефактов, старых архивов и кешей.
Распакованный проект устанавливается командой `npm run setup` по корневому README.

Подробные отчёты: [frontend](frontend/CHECKS_FRONTEND.md),
[backend](backend/CHECKS_BACKEND.md), [database](database/CHECKS_DATABASE.md).
