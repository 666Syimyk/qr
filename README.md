# Emergency QR — полный проект

Объединённый проект по спецификации `emergency-qr-v1`: сайт и приложение
Expo от Мики, HTTP API от Ризо, SQLite от Ади и общие команды запуска.
Создание, редактирование, отключение, замена QR и удаление работают с
реальной базой. Публичная карточка открывается в браузере без авторизации.

Интерфейс обновлён по макету: красный акцент `#E51D36`, горный фон главной
на телефоне и компьютере, создание за три шага, отдельные экраны QR и профиля,
страницы «О проекте» и «Помощь». Секретный ключ и опасные действия находятся
в профиле. Публичную ссылку можно отправить или скопировать; браузер также
скачивает настоящий QR в PNG 1120×1120 с белой рамкой, без логотипа поверх кода.

| Папка | Назначение |
| --- | --- |
| `frontend/` | Expo Router, React Native и web, формы, QR, управление карточкой |
| `backend/` | Express API, авторизация владельца, валидация, раздача сайта |
| `database/` | SQLite, миграция, репозиторий данных |
| `scripts/` | Установка, настройка URL, запуск проверок |

Результаты и ограничения проверки: [CHECKS_PROJECT.md](CHECKS_PROJECT.md).

## Быстрый запуск

1. Распакуйте `emergency-qr.zip`. Откройте папку, в которой рядом находятся
   `frontend/`, `backend/`, `database/`, `scripts/` и этот `package.json`.
2. Установите **Node.js 24.x** и откройте терминал в `emergency-qr`.
3. Выполните:

```sh
npm run setup
npm run configure
npm run configure -- --host=ФАКТИЧЕСКИЙ_IP
npm run build:web
npm start
```

`configure` без аргументов только показывает IPv4-интерфейсы. Замените
`ФАКТИЧЕСКИЙ_IP` на адрес компьютера в сети телефона, например `192.168.1.50`.
Не выбирайте VPN автоматически. `setup` последовательно устанавливает
зависимости трёх папок; npm workspaces не используются. У каждой части свой lock-файл.

Во втором терминале из того же корня:

```sh
npm run mobile
```

В Windows при запрете PowerShell на запуск `npm.ps1` используйте `npm.cmd`
вместо `npm`. Не требуется менять системную политику выполнения.

## Телефон, браузер и два разных QR

- Компьютер и телефоны должны находиться в одной доступной сети. Гостевая
  Wi-Fi сеть может блокировать связь между устройствами.
- Сначала откройте на телефоне `http://ФАКТИЧЕСКИЙ_IP:3001/api/v1/health`.
  Ожидается `{"ok":true,"contractVersion":"emergency-qr-v1"}`.
- Сайт открывается по `http://ФАКТИЧЕСКИЙ_IP:3001`. Backend слушает
  `0.0.0.0:3001`, Expo — порт `8081`.
- **QR Expo** запускает приложение для разработки в Expo Go.
  **QR карточки** содержит серверный `publicUrl` и открывает `/q/<token>`
  в обычном браузере без регистрации и Expo Go.
- `localhost` и `127.0.0.1` на телефоне означают сам телефон, а не компьютер.
  Expo tunnel не публикует отдельный backend.
- Если мешает firewall, разрешите только нужные локальные порты 3001 и 8081
  в доверенной сети. Полностью отключать firewall не нужно.
- После смены API URL перезапустите Expo и повторите `npm run build:web`.
- При смене сети или LAN-IP повторите настройку адресов и перезапустите backend.
  Сохраните новые PNG/распечатки: старый QR содержит прежний origin и сам не меняется.

Если `frontend/dist/index.html` ещё нет, API работает, а браузер получает
HTTP 503 и «Сначала выполните npm run build:web». После сборки сервер подхватит
файлы автоматически. Для Expo требуется `web.output='single'`; QR-страницы
обслуживаются SPA fallback, без предварительной генерации секретных адресов.

## Настройки

`npm run configure -- --host=<LAN_IP>` согласованно записывает
`frontend/.env` и `backend/.env`. В API URL включён `/api/v1`.
Перед перезаписью любого существующего `.env` нужен явный `--force`.
Он перезаписывает **оба** файла, включая ручные дополнительные настройки.
Команда не создаёт ключей владельцев.

Для уже подготовленного внешнего HTTPS-адреса:

```sh
npm run configure -- --origin=https://demo.example.org
```

Это только настройка URL: команда не создаёт домен, HTTPS, tunnel или деплой.
Внешний reverse proxy должен пересылать сайт и API на backend. HTTP допустим
только для локального демо с вымышленными данными.

Backend читает `.env` из `backend/`, а относительные `DATABASE_PATH` и
`WEB_DIST_PATH` разрешает от этой папки независимо от рабочего каталога.
Переменные процесса имеют приоритет над `.env`. `PUBLIC_WEB_ORIGIN` — только
origin, без пути, query, fragment и учётных данных. Один завершающий `/`
удаляется. Заголовкам Host/X-Forwarded-Host сервер не доверяет для ссылок.

`ALLOWED_ORIGINS` — список точных web origins через запятую. Локальная
настройка включает сайт на 3001, Expo web на 8081 и `http://localhost:8081`.
Запросы native без `Origin` допускаются, но ключ для `/me/*` обязателен.
Недопустимый Origin отклоняется с JSON 400 / `VALIDATION_ERROR`, до записи.

Лимиты по умолчанию: 10 созданий за 10 минут, 120 owner-запросов за минуту,
120 публичных чтений за минуту на IP. Их можно изменить переменными из
`backend/.env.example`. Хранилище лимитов — память одного процесса, сбрасывается
при перезапуске. Сами IP и запросы не логируются.

По умолчанию `trust proxy=false`. Для известного reverse proxy задайте
`TRUST_PROXY` в окружении backend: список точных IP-адресов или CIDR через
запятую, и настройте на proxy перезапись forwarded-заголовков. Значения `true`,
число промежуточных proxy, имена хостов и CIDR `/0` отвергаются. Исходники менять
не требуется. Без настройки proxy все его клиенты могут делить один лимит.
Отключите access-логи с полными
путями `/q/<token>` и `/api/v1/public/cards/<token>` на самом proxy.

## Проверка перед показом

```sh
npm run check
npm run lint
npm run test:all
npm run test:configure
npm --prefix frontend exec -- playwright install chromium
npm run test:browser
npm run test:e2e
```

`test:all` запускает unit-тесты frontend, API, репозитория и интеграцию
API с настоящей SQLite. `test:e2e` собирает отдельный тестовый сайт,
запускает настоящий backend на `127.0.0.1:3101` с временной базой и проходит
весь жизненный цикл в Chromium. Проверяется также перезапуск процесса
и доступ из второго изолированного браузера с шириной экрана телефона.
Тест не изменяет вашу базу и сборку `frontend/dist`. Порт 3101 должен быть свободен.

`test:browser` отдельно собирает `.integration/mock-web` и запускает браузерные
регрессии с подменным API на `127.0.0.1:4274`. Адрес тестового API задаёт
`scripts/browser.mjs`; вручную менять `.env` не нужно. Эта команда также
не перезаписывает `frontend/dist`. Порт 4274 должен быть свободен.

Другие команды:

```sh
npm test
npm --prefix backend test
npm --prefix database test
npm --prefix frontend test
npm run test:integration
```

`npm test` проверяет сервер и базу; `test:all` дополнительно включает frontend
и SQLite-интеграцию. Отдельные браузерные проверки ошибок с подменным API
описаны в [инструкции frontend](frontend/README_FRONTEND.md).

Ручная проверка капитана: создать карточку с вымышленными данными → сохранить
ключ → сканировать QR другим телефоном → изменить данные → обновить публичную
страницу → отключить/включить → заменить QR → убедиться в недоступности старого
QR → перезапустить сервер и проверить сохранность → удалить. Потерянный ключ
не восстанавливается. Чужой или публичный ключ не должен позволять управление.

Это демонстрационная карточка контакта и добровольно опубликованной информации.
Она не заменяет экстренную помощь. Любой обладатель публичной ссылки может
скопировать данные; отзыв QR не удаляет чужие копии. Не используйте реальные
персональные данные на демонстрации. Проверка web не означает проверку native.
APK/IPA и публикация в магазинах не выполнены.

## Постоянный домен и HTTPS

Подготовлены [инструкция развёртывания](docs/DEPLOYMENT.md) и конфигурация
`deployment/` для Docker Compose, Caddy и постоянного тома SQLite. Требуются
свой домен и сервер с работающим Docker Engine. Compose-конфигурация проверена;
локальный Docker Engine недоступен, поэтому сборка образа, запуск контейнеров,
выдача сертификата и внешний HTTPS-адрес пока не подтверждены. Публичный деплой
не выполнен. Команда `configure --origin=...` сама по себе его не создаёт.

Состав исходного архива: код, тесты, lock-файлы, `.env.example` и документация.
Зависимости, настоящие `.env`, базы, ключи, результаты тестов и локальные
сборки в архив не включены. На другом компьютере выполните быстрый запуск выше.
