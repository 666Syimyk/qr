# Проверки frontend

Дата: 1 октября 2026 года. Windows, Node.js **24.18.0**, npm **11.16.0**. Отчёт о frontend Мики, контракт `emergency-qr-v1`. Проверки объединённого проекта с настоящими backend и SQLite описаны отдельно в [CHECKS_PROJECT.md](../CHECKS_PROJECT.md).

## Выполнено

- Реализованы `/`, `/create`, `/my`, `/profile`, `/edit`, `/restore`, `/q/[publicToken]`, `/about`, `/help`: общий React Native UI для web/native и API-клиент. Учебные экраны шаблона удалены.
- Выполнен редизайн по макету: красный `#E51D36`, горная главная для desktop/mobile, компактный QR, отдельный профиль и мобильная навигация. Используются инициалы; несуществующие в контракте фото и дата рождения не добавлялись.
- Создание за три шага с валидацией каждого шага, отдельным согласием и предпросмотром; заметка по умолчанию скрыта. Кнопки «Назад» сохраняют черновик, серверные ошибки возвращают к нужному полю.
- QR из серверного `publicUrl`: чёрный/белый, 256 px, `quietZone=32`, без внешнего QR-сервиса и логотипа поверх кода. Браузер сохраняет настоящий PNG 1120×1120 из отображаемого SVG.
- Управление карточкой, повторный ввод ключа, явные подтверждения отключения/замены QR/удаления, выход и очистка после 401.
- Web-ключ только в памяти; native-адаптер SecureStore. Ошибки хранилища не выдаются за успешное сохранение. Ключ можно сохранить вручную даже после сбоя последующего GET карточки.
- Публичный экран с явной кнопкой звонка, отключёнными демо-номерами, обновлением и очисткой устаревших данных при ошибках.
- Копирование по HTTPS и через синхронный HTTP fallback; отказ ведёт к ручному выделению, а не ложному сообщению об успехе. Web Share / native Share передают только публичную ссылку. На native скачивание PNG не предлагается.

Текущий `scripts/browser.mjs` задаёт `EXPO_PUBLIC_API_URL=http://127.0.0.1:3001/api/v1` только дочернему процессу, собирает `.integration/mock-web` и запускает preview на `127.0.0.1:4274`. ## Что доказано тестами

API: точные пути, методы и тела; Authorization только на `/me/*`; обработка 204, 400/401/404/429/500, ошибок сети, таймаута/AbortController, HTML вместо JSON и неполных ответов. Нормализация адреса и отказ от URL с credentials/path/query вне контракта. Для любого публичного 404 показывается одинаковое сообщение «Карточка недоступна: ссылка может быть отключена или заменена», независимо от текста ошибки сервера.

Сессия: выход и защищённый 401 очищают память и вызывают очистку хранилища; ошибки чтения/записи/удаления отображаются; отложенное чтение и сохранение не возвращают ключ после выхода; старый 401 не очищает новую сессию. Это тесты настоящего SessionController с тестовым адаптером хранения, а не подтверждение работы SecureStore на телефоне.

Браузер: адаптивные главная и форма на 390/1280 px; согласие и нормализация; создание с одним POST; QR только после ответа; ключ скрыт до явного действия; сохранение ключа при сбое GET после создания; редактирование без смены QR; сохранность черновика при смене видимости вкладки; отмена и подтверждение опасных действий; отключение и замена QR без смены статуса; удаление и выход; скрытая заметка отсутствует в публичном DOM; демо-звонок заблокирован; на ошибке/404 нет предыдущей карточки; неверный ключ не даёт доступ; перезагрузка web теряет ключ; активный 401 возвращает к вводу ключа.

Дополнительно после редизайна проверены верхняя и нижняя навигация шагов, сохранность всех полей при возврате, возврат на шаг с ошибкой сервера, доступность верхней кнопки на телефоне после прокрутки, переходы профиля/помощи/информации о проекте и мобильных вкладок. Браузерные тесты читают фактический буфер обмена для ссылки и явно раскрытого ключа; проверяют отказ, HTTP fallback и отсутствие временных полей, отправку ссылки с fallback, скачивание настоящего PNG 1120×1120 и размещение QR внутри панели при 320 px.

Helper-тесты проверяют вызов Clipboard/Share непосредственно в событии нажатия, обработку отмены отправки без скрытого копирования, точное различение успеха/отказа, очистку временного секретного текста и освобождение временных URL экспорта. Это проверки границ браузерных API; они не подтверждают системный Clipboard или Share на физическом телефоне.

Финальный проход с настоящими Chromium, API и SQLite после LAN-пересборки подтвердил повторный вход по ключу, успешное HTTP-копирование и скачивание PNG. Сохранены 12 снимков в `.integration/redesign/`: главная 1280/390/320, about 1280/390, help 390, my 390, profile 390/1280, public 1280/390/320. Горизонтального переполнения и JS-исключений нет. После последних правок оформления и настройки сети успешно повторены web и all-platform экспорты; это проверка компиляции, без запуска физического устройства. Финальный скачанный PNG 1120×1120 декодирован в точный publicUrl настоящего LAN backend.

Дополнительно вручную через Playwright проверены размеры 320/390/1280 px: после исправления узкой шапки элементы главной не выходят за viewport. Просмотрены реальные снимки главной, формы и экрана владельца. Изображение QR из браузерного теста успешно декодировано локальным `cv2.QRCodeDetector`: результат **в точности равен publicUrl тестового ответа**, не ownerToken. Это программная проверка изображения, не сканирование вторым телефоном.

После проверки исправлены две найденные ошибки: потеря черновика при переключении приложения в фон и гонка перехода после добровольного выхода/удаления. Регрессионные браузерные проверки прошли.

Повторный аудит при объединении проекта выявил и исправил ещё три ошибки. После успешного PUT экран сразу переходит к загрузке `/my`: сбой последующего чтения больше не оставляет форму для повторной отправки уже сохранённой редакции. Раскрытый ключ снова скрывается при уходе с маршрута или переводе приложения/вкладки в фон. Публичный 404 нормализован к заданному нейтральному тексту. Перед исправлениями два новых браузерных теста и новый API-тест воспроизвели сбои; после исправлений полный набор прошёл.

При настоящей интеграционной проверке дополнительно исправлено состояние галочки
согласия для доступности: RN Web этой версии игнорирует `accessibilityState.checked`,
поэтому добавлены явные `aria-checked` и `aria-disabled`. Регрессия проверяет
переходы выключено → включено → выключено. Команды сборки и запуска очищают кеш
Metro: при смене API URL в окружении он мог оставлять старый адрес в JS.

## Не проверено и не входит в этот пакет

- Тесты `tests/browser.spec.ts` проверяют frontend с перехваченными ответами и сами по себе **не доказывают интеграцию с backend/SQLite**. `tests/preview-server.mjs` выдаёт статические файлы и не реализует API. Результаты отдельных настоящих интеграционных проверок находятся в [CHECKS_PROJECT.md](../CHECKS_PROJECT.md).
- **Запуск в Expo Go на физическом Android/iPhone или эмуляторе не проверен.** Подключённое устройство не использовалось; `adb` в окружении не найден. Нативный экспорт не заменяет такой тест.
- В рамках frontend-аудита не проверены настоящий SecureStore, системный Share/Clipboard/tel, камера второго телефона, LAN/firewall. Сохранность данных после перезапуска backend и серверные права доступа проверяются отдельно в общем отчёте.
- Если сам ответ POST создания утрачен в сети до получения `ownerToken`, у клиента нет способа восстановить выданный сервером ключ: контракт не предусматривает восстановление или идемпотентное повторение. Проверена сохранность уже полученного ключа при сбое последующей загрузки карточки и при ошибке локального сохранения.
- Не созданы APK/IPA, внешний деплой или полноценные аккаунты. Прототип не заявляется готовым к медицинскому применению.
- Для внешнего HTTPS подготовлены [инструкция](../docs/DEPLOYMENT.md) и Docker/Caddy-конфигурация. `compose config` проверен, но Docker Engine недоступен: контейнеры, публичный домен и сертификат пока не проверены.
- Npm audit сообщает о транзитивных предупреждениях в цепочках Expo/xcode/uuid и Expo Router/query-string/decode-uri-component. Проверены установленные `xcode@3.0.1 → uuid@7.0.3` и `query-string@7.1.3 → decode-uri-component@0.2.2`. Исправленный decoder 0.5.0 использует ESM, а установленный query-string 7 — CommonJS: совместимого обновления в объявленном диапазоне нет. Автоматическое предложение npm включает несовместимый откат Expo; `audit fix --force` и принудительные замены транзитивных модулей не применялись. Проверка expo-doctor не является аудитом безопасности.

Для общего показа дополнительно нужен сценарий с двумя физическими устройствами из исходного задания. Не следует представлять браузерные фикстуры или экспорт JS/Hermes как проверку на телефоне.
