# Emergency QR — frontend Мики

Сайт и нативные экраны Expo на русском, контракт `emergency-qr-v1`. Реализованы `/`, `/create`, `/my`, `/profile`, `/edit`, `/restore`, `/q/[publicToken]`, `/about`, `/help`. Эта папка содержит **только frontend**. Для реального создания и управления карточкой нужны соседние `backend/` и `database/`; запуск объединённого проекта описан в [корневом README](../README.md). Рабочее приложение не использует фиктивные ответы или localStorage вместо сервера.

Интерфейс соответствует новой визуальной направленности макета: красный `#E51D36`, горная главная для desktop/mobile, создание карточки за три шага, компактный экран QR и отдельный профиль. Поля даты рождения и фотографии не добавлены в API: вместо вымышленного фото используются инициалы владельца.

## Запуск

Node.js 24.x и npm. Из корня объединённого проекта:

```powershell
cd frontend
npm ci
Copy-Item .env.example .env
```

Отредактируйте `.env`, заменив пример IP на **реальный доступный LAN-IP компьютера**:

```dotenv
EXPO_PUBLIC_API_URL=http://192.168.1.10:3001/api/v1
```

Это полный адрес API с `/api/v1`. Допускается один завершающий `/`. Не помещайте сюда секретный ключ. Для телефона не используйте `localhost` или `127.0.0.1`: эти адреса укажут на сам телефон. При отсутствии настройки главная страница открывается, а запросы показывают ошибку настройки.

Сайт в режиме разработки:

```powershell
npm run web
```

Expo Go:

```powershell
npm start
```

Оба режима используют порт 8081; запускайте нужный режим в отдельном терминале. Компьютер и телефон должны быть в одной доступной сети. Откройте на телефоне `http://ВАШ_IP:3001/api/v1/health` и проверьте доступ к backend перед проверкой приложения. Используйте Expo Go, совместимый с SDK 57. Встроены совместимые SecureStore, Clipboard и SVG. При смене адреса API перезапустите Expo и пересоберите web.

**QR терминала Expo запускает среду разработки. QR карточки открывает публичный сайт в браузере. Это разные коды.** Expo tunnel не публикует отдельный backend. Не отключайте firewall полностью; при необходимости разрешите только нужные порты в доверенной локальной сети.

LAN-IP может измениться при смене сети. Найдите его через корневой `npm run configure`, согласуйте оба `.env`, пересоберите сайт и перезапустите backend/Expo. Заново сохраните QR: старый PNG или распечатка продолжают содержать прежний адрес.

## Сборка и передача backend

```powershell
npm run build:web
```

Результат — `frontend/dist`. Expo использует `web.output="single"`: для неизвестных клиентских маршрутов, включая `/q/<token>`, backend должен отдавать `dist/index.html`. API должен быть зарегистрирован раньше fallback; отсутствующие JS/CSS должны возвращать 404. Не генерируйте страницы для всех QR заранее.

Корневая команда `configure` согласует `PUBLIC_WEB_ORIGIN` с адресом готового сайта, а `ALLOWED_ORIGINS` — с web origins сайта и Expo. Frontend кодирует **ровно `publicUrl` из ответа сервера**, а не адрес API или Expo. Обновление данных сохраняет тот же QR; замена QR и статус обрабатываются сервером.

`public/index.html` задаёт русский язык, `referrer=no-referrer` и `robots=noindex,nofollow` для single-page экспорта. `public/robots.txt` запрещает индексирование. Backend отдельно обязан устанавливать HTTP-заголовки `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex, nofollow`. Метатеги не заменяют заголовки и контроль доступа. Внешнее размещение требует HTTPS; локальное HTTP-демо — только с вымышленными данными.

## Ключ и приватность

- На native: Expo SecureStore. При ошибке сохранения ключ остаётся в памяти, выводится предупреждение и доступно ручное сохранение. Ошибка очистки также показывается с возможностью повтора.
- На web: только память текущего приложения. После обновления страницы нужен повторный ввод сохранённого ключа. Нет localStorage, sessionStorage, cookie-auth или помещения ключа в URL.
- Ключ находится в `/profile`, скрыт до явного нажатия и снова скрывается при уходе с экрана или в фон. Он доступен для ручного сохранения даже при сбое загрузки карточки. Копируйте его отдельно от QR в надёжное место. При потере ключа восстановления по имени/телефону/почте нет.
- Выход удаляет локальный ключ; удаление карточки вызывает DELETE и очищает ключ после 204. Защищённый 401 очищает сессию. Отложенный ответ старой сессии не очищает новую.
- Публичные запросы не получают Authorization. Их ответы перечитываются при открытии, возвращении приложения и по кнопке обновления; при загрузке/ошибке/404 предыдущие сведения убираются.
- Заметка по умолчанию скрыта. Согласие не предустановлено; при редактировании подтверждается снова. Предпросмотр показывает только выбранные поля.
- Номера `+999…` — демонстрационные: звонок заблокирован. Другой валидный номер открывает `tel:` только по нажатию; реальных звонков при проверке не выполнялось.
- Замена QR, отключение и удаление требуют подтверждения в общем для web/native диалоге.

## QR, копирование и навигация

На `/my` находятся публичный QR, контакт, отправка ссылки, изменение и включение/отключение карточки. Секретный ключ, замена QR, выход и удаление перенесены в `/profile`. Мобильная навигация ведёт на главную, QR и профиль. В форме верхняя и нижняя кнопки «Назад» возвращают на предыдущий шаг и сохраняют черновик.

QR чёрный на белом, 256 px, с `quietZone=32`, без логотипа поверх модулей. В браузере «Скачать QR» создаёт PNG **1120×1120** из отображаемого SVG; токен не передаётся внешнему сервису. Native показывает системную отправку публичной ссылки; кнопка скачивания PNG там не заявляется.

В безопасном браузерном контексте Clipboard API вызывается прямо из нажатия. Для локального HTTP по LAN используется синхронный `execCommand('copy')`; временное поле очищается и удаляется. Если браузер запрещает оба способа, интерфейс честно предлагает выделить видимую строку вручную. Отказ не отображается как успешное копирование. Native проверяет результат `Expo Clipboard.setStringAsync`. Кнопка отправки использует системный Share или Web Share, а при отсутствии Web Share — копирование публичной ссылки. Секретный ключ никогда не передаётся этой кнопке.

## Проверки

```powershell
npm run typecheck
npm test
npm run lint
npx expo-doctor
npm run build:web
```

Браузерные регрессии используют перехваты ответов в `tests/browser.spec.ts`. Они **не заменяют интеграцию с backend/SQLite**. Из корня объединённого проекта:

```powershell
npm --prefix frontend exec -- playwright install chromium
npm run test:browser
npm run test:e2e
```

`scripts/browser.mjs` создаёт отдельный экспорт `.integration/mock-web`, задаёт тестовый адрес API в окружении дочернего процесса и запускает `tests/preview-server.mjs` на `127.0.0.1:4274`. Этот сервер не реализует API. `.env` и рабочий `frontend/dist` не меняются. `test:e2e` использует другой экспорт, настоящий backend на 3101 и временную SQLite. Для обычной сборки по-прежнему служит `npm run build:web`.

Исходники: `src/app/` — маршруты; `src/components/` — общий UI; `src/lib/api.ts` — HTTP, таймаут и типизированные ошибки; `src/lib/session*` — сессия и защита от гонок; `storage.web/native.ts` — хранение; `src/types/contracts.ts` — точные типы общего контракта.

Результаты и ограничения frontend: [CHECKS_FRONTEND.md](CHECKS_FRONTEND.md). Настоящая интеграция с API и SQLite: [CHECKS_PROJECT.md](../CHECKS_PROJECT.md). В полном исходном архиве `frontend/`, `backend/` и `database/` находятся рядом. `node_modules`, реальные `.env`, пользовательская SQLite, тестовые артефакты и локальные сборки не входят в исходный архив. Конфигурация постоянного HTTPS-адреса подготовлена в [docs/DEPLOYMENT.md](../docs/DEPLOYMENT.md); это ещё не выполненный внешний деплой.

Технические источники: [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/), [экспорт SPA](https://docs.expo.dev/guides/publishing-websites/), [SecureStore](https://docs.expo.dev/versions/v57.0.0/sdk/securestore/), [react-native-qrcode-svg](https://github.com/Expensify/react-native-qrcode-svg).
